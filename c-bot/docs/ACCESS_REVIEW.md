# Access Review Procedure

Perform an access review at least quarterly and after any material role, vendor, architecture, or security change. The accountable owner must export the current user and administrator list, compare it to approved roles, remove stale or excessive access, review privileged API/IAM roles, validate MFA settings, and retain the completed review record with date, reviewer, findings, and remediation. Emergency access must be time-limited, logged, and reviewed after use.

For the current beta, verify that only approved testers can sign in and that no person can access another practice’s information. Before PHI enablement, formalize user provisioning, deprovisioning, role approval, temporary access, service-account ownership, and access-review evidence.
